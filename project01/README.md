# Project 1

숫자 문자열, 영어 수 표현, 한국어 수 표현을 서로 번역합니다.

## 1. 제출 파일

```text
project01/
├── 1_LSTM_multi.ipynb      # LSTM 학습 및 추론(Greedy, Beam & Pivot) : 1개의 모델
├── 1_LSTM_multi.pt         # 6방향 1모델
├── 2_GRU_Attn.ipynb        # GRU + Attention 학습 및 추론(Greedy) : 6개의 모델
├── en2ko.pt                # 영어 → 한국어
├── en2num.pt               # 영어 → 숫자
├── ko2en.pt                # 한국어 → 영어
├── ko2num.pt               # 한국어 → 숫자
├── num2en.pt               # 숫자 → 영어
├── num2ko.pt               # 숫자 → 한국어
└── README.md
```

각 팀원들이 자유롭게 practice01 디렉토리에서 실험을 해보았고,
그 중 2가지 결과물을 제출합니다.

1_LSTM_Multi는 Attention 없이 LSTM만으로 학습한 코드입니다.
- 6방향 번역을 1개의 모델(1_LSTM_Multi)로 학습하였으며, 테스트셋에서는 99% 이상의 준수한 성능을 보였습니다.
- 다만 30000 (삼만)과 같이 0이 연속되는 숫자는 정상적으로 번역하지 못하는 모습을 보여, Pivot Translation 및 Beam을 적용하였습니다.
- 테스트 편이를 위해 입력 언어가 무엇인지 모델이 직접 알아보는 lang_fc 헤드를 추가했습니다.
- 디코딩 알고리즘을 Beam으로 바꾸는 것은 큰 차이가 없었고, 영어나 한글을 숫자로 먼저 번역하면 성능이 조금 나았습니다.
- 다만 one million (1,000,000) 같은 숫자는 Pivot을 통해서도 번역하지 못했습니다.

2_GRU_Attn은 GRU와 Scaled Dot Attention을 활용하여 학습한 코드입니다.
- 각 방향에 대해 6개의 모델을 학습했습니다: en2ko, en2num, ...
- one million은 번역하지 못했지만, 30000 같은 숫자는 Pivot 없이도 잘 번역했고 테스트셋과 임의 입력 값에 대해 전반적으로 보다 나은 성능을 보였습니다.

제출물에서 제외된 실험
- character 단위로 학습: 다국어 학습을 위해 적용했으나, 추론 속도가 매우 느림
- data augmentation: 추가 데이터를 학습하여 성능을 개선했으나, 모델 구조 학습 목적과는 부합하지 않아 제외


언어 코드는 `num`(숫자), `en`(영어), `ko`(한국어)입니다. 9절까지 실행하면 `run_demo()`를 호출하여 입력 언어를 규칙으로 판별하고 나머지 두 언어로 번역할 수 있습니다.

#### 새로 학습하기

#### 번역 원리

##### ① 같은 숫자의 표현을 짝짓습니다

영어와 한국어 데이터 파일을 숫자 문자열을 기준으로 합칩니다. 하나의 숫자에 대해 존재하는 표현들을 서로 짝지어 최대 6방향의 번역 쌍을 생성합니다. 영어와 한국어 표현이 모두 존재하는 경우에만 영어↔한국어 번역 쌍을 생성합니다.

##### ② 언어별로 입력을 토큰화합니다

숫자와 한국어는 문자 단위, 영어는 공백을 기준으로 단어 단위로 나눕니다. 세 언어는 하나의 어휘 사전과 임베딩을 공유합니다. 사전에 없는 토큰은 UNK로 처리합니다.

```text
"123"          → ["1", "2", "3"]
"백이십삼"     → ["백", "이", "십", "삼"]
"twenty three" → ["twenty", "three"]
```

##### ③ LSTM이 목표 언어를 포함한 입력을 읽고 번역합니다

```text
목표 언어 토큰 + 입력 토큰 + EOS → Encoder LSTM
                                      ↓ 최종 hidden state, cell state
BOS 또는 이전 출력 토큰 ─────────→ Decoder LSTM → 다음 토큰 점수
```

목표 언어는 Encoder 입력 앞에 `<2num>`, `<2en>`, `<2ko>` 중 하나를 붙여 지정합니다. Decoder LSTM은 Encoder의 최종 hidden state와 cell state를 초기 상태로 사용하며 BOS에서 출발합니다. Attention과 입력 언어 분류 헤드는 사용하지 않습니다.

번역 함수에는 입력 언어와 목표 언어를 전달합니다. 9절의 직접 입력 테스트에서는 ASCII 숫자 여부와 ASCII 문자 여부를 기준으로 입력 언어를 판별합니다.

##### ④ 정답과 비교하며 학습합니다

학습할 때는 이전 정답 토큰을 Decoder에 입력합니다(teacher forcing). 다음 토큰 예측에 CrossEntropyLoss를 적용하고 PAD는 손실 계산에서 제외합니다. Adam으로 모델 가중치를 조정하여 번역 손실을 줄입니다.

##### ⑤ 실제 번역에서는 스스로 생성합니다

Greedy Decoding은 BOS에서 출발하여 매 단계에서 점수가 가장 높은 토큰 하나를 선택해 다음 입력으로 사용합니다. EOS가 나오거나 최대 생성 길이에 도달하면 종료합니다. 영어 출력은 토큰 사이에 공백을 넣고, 숫자와 한국어 출력은 토큰을 그대로 이어 붙입니다.

##### ⑥ Pivot Translation 및 Beam Search

Pivot Translation은 영어와 한국어 사이의 직접 번역 대신 숫자 문자열을 중간 표현으로 사용합니다. 동일한 모델을 두 번 사용하며, 중간 출력이 ASCII 숫자 문자열인지 확인합니다. 숫자를 입력하면 나머지 두 언어로 직접 번역합니다.

```text
영어 → 숫자 → 한국어
한국어 → 숫자 → 영어
```

Beam Search는 매 단계에서 누적 로그확률이 높은 후보를 기본 3개씩 유지합니다. 모든 후보가 EOS로 종료되거나 최대 생성 길이에 도달하면 누적 점수가 가장 높은 후보를 반환합니다. 길이 정규화는 적용하지 않습니다.

노트북 10절에서 `pivot_translate()`와 `translate_beam()`을 정의하고 `thirty thousand`를 예제로 직접 번역과 비교합니다. 두 방법 모두 모델을 다시 학습하지 않고 적용할 수 있습니다. 수정된 노트북에는 해당 비교의 실행 결과가 저장되어 있지 않습니다.

```python
pivot_translate("thirty thousand")
translate_beam("thirty thousand", "en", "ko", beam_width=3)
```

#### 번역 원리

##### ① 같은 숫자의 표현을 짝짓습니다

두 데이터 파일을 행 번호가 아니라 **숫자 문자열**로 연결합니다. 숫자→한국어 모델에는 숫자 문자열을 입력으로, 해당 한국어 표현을 정답으로 줍니다. 영어↔한국어는 두 파일에 모두 존재하는 숫자의 표현만 사용합니다.

##### ② 입력을 작은 조각으로 나눕니다

숫자와 한국어는 문자 단위, 영어는 단어 단위로 나눕니다.

```text
"123"          → ["1", "2", "3"]
"백이십삼"     → ["백", "이", "십", "삼"]
"twenty three" → ["twenty", "three"]
```

이 조각을 토큰이라고 합니다. 토큰을 ID로 바꾸고 학습 가능한 벡터로 변환해 신경망에 전달합니다. 원래 숫자 문자열 자체를 정수로 바꾸어 계산하지는 않습니다.

##### ③ GRU가 읽고 Attention을 참고해 출력합니다

```text
입력 문자열 → 토큰 → Encoder GRU → 입력 위치별 정보
                                      ↓ Attention으로 가중합
이전 출력 토큰 → Decoder GRU → 입력 정보와 결합 → 다음 토큰 점수
```

인코더는 입력을 순서대로 읽습니다. 디코더는 인코더의 마지막 상태를 받아 출력을 시작합니다. Attention은 매 출력 단계에 입력 위치별 중요도를 계산하고, 그 비중에 따라 입력 정보를 섞어 다음 토큰 예측에 사용합니다. 입력 한 위치만 고르는 방식은 아닙니다.

##### ④ 정답과 비교하며 학습합니다

학습할 때는 이전 정답 토큰을 알려 주면서 다음 토큰을 맞히도록 합니다(teacher forcing). 정답의 예측 확률이 낮으면 오차가 커집니다. Adam으로 모델 가중치를 조정하여 이 오차를 줄입니다. 길이를 맞추는 PAD 토큰은 오차 계산에서 제외합니다.

##### ⑤ 실제 번역에서는 스스로 생성합니다

시작 토큰 BOS에서 출발해, 매 단계 출력 가능한 토큰 중 점수가 가장 높은 하나를 선택합니다(Greedy). 선택한 토큰을 다음 단계의 입력으로 사용하며 종료 토큰 EOS가 나오면 멈춥니다. 시험 평가에서도 이전 정답을 알려 주지 않습니다.

#### 데이터 분할과 학습 설정

같은 숫자가 학습용과 시험용에 동시에 들어가지 않도록 숫자 키를 먼저 나누고, 모든 방향에 같은 분할을 적용합니다. 자릿수와 두 파일에 포함되는 여부별로 그룹을 나누어 약 80%/10%/10%를 배정합니다. `0`의 표현을 학습할 수 있도록 숫자 `0`은 학습용에 둡니다. 사전도 학습용 표현에서만 만듭니다.

| 방향 | 학습 | 검증 | 시험 |
|---|---:|---:|---:|
| 숫자↔영어, 숫자↔한국어: 각 방향 | 79,998 | 10,001 | 10,001 |
| 영어↔한국어: 각 방향 | 10,188 | 1,275 | 1,275 |

| 항목 | 설정 |
|---|---|
| 난수 시드 | 42 |
| 임베딩 크기 / GRU 은닉 크기 | 128 / 256 |
| GRU 층 수 / Dropout | 1 / 0.1 |
| 배치 크기 | 256 |
| 최적화 / 학습률 | Adam / 0.001 |
| 최대 학습 횟수 | 30 epoch |
| 조기 종료 | 검증 오차가 5회 연속 개선되지 않으면 종료 |
| 모델 저장 | 검증 오차가 이전 최저값보다 0.00001 넘게 감소하면 저장 |
| 기울기 최대 노름 | 1.0 |
| 생성 한도 | EOS를 포함해 최대 32단계 |

#### 저장 모델 평가 결과

공백을 정리한 **전체 출력 문자열이 정답과 일치하고 EOS로 종료해야** 정답입니다. 아래는 제공 모델을 제출 노트북으로 다시 평가한 결과입니다.

| 방향 | 정답 / 시험 수 | 정답률 |
|---|---:|---:|
| 숫자 → 영어 | 9,991 / 10,001 | 99.90% |
| 영어 → 숫자 | 9,996 / 10,001 | 99.95% |
| 숫자 → 한국어 | 9,997 / 10,001 | 99.96% |
| 한국어 → 숫자 | 9,998 / 10,001 | 99.97% |
| 영어 → 한국어 | 1,274 / 1,275 | 99.92% |
| 한국어 → 영어 | 1,272 / 1,275 | 99.76% |

영어↔한국어 공통 데이터에는 9~10자리 숫자가 없어 해당 범위를 학습·평가하지 못했습니다. 8자리 시험 데이터도 한 개뿐이며 두 방향 모두 오답입니다. 높은 전체 정답률이 모든 자릿수에서 같은 성능을 의미하지는 않습니다. 자릿수별 표본 수와 오답 예시는 노트북에서 확인할 수 있습니다.
