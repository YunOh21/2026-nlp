# Project 1 — 숫자·영어·한국어 번역

숫자 문자열, 영어 수 표현, 한국어 수 표현을 서로 번역합니다. 변환 규칙을 직접 작성하는 대신, 제공된 입력과 정답 쌍으로 **GRU Encoder–Decoder + Attention**을 학습했습니다. 출력은 **Greedy decoding**으로 생성합니다.

**방향별로 독립적인 모델을 하나씩, 총 6개 사용합니다.** 영어↔한국어도 숫자를 중간에 거치지 않고 직접 번역합니다. 일반 문장이 아닌 수 표현을 대상으로 합니다.

## 1. 제출 파일

저장소의 `practice01/sungbin/`에 아래 10개 파일을 함께 둡니다. 모든 구현은 노트북 안에 있어 별도의 Python 소스 파일이 필요하지 않습니다.

```text
practice01/sungbin/
├── README.md          # 설명과 실행 방법
├── requirements.txt   # PyTorch 의존성
├── num2text.ipynb      # 전체 코드, 설명, 평가 출력, 사용 예제
├── num2word.zip       # 제공 데이터: num2txt.txt, num2kor.txt
├── num2en.pt          # 숫자 → 영어
├── en2num.pt          # 영어 → 숫자
├── num2ko.pt          # 숫자 → 한국어
├── ko2num.pt          # 한국어 → 숫자
├── en2ko.pt           # 영어 → 한국어
└── ko2en.pt           # 한국어 → 영어
```

`.pt`에는 학습한 가중치, 입력·출력 토큰 사전, 모델 설정이 들어 있습니다. ZIP은 압축을 풀지 않아도 노트북이 직접 읽습니다.

## 2. 실행 방법

### 기본 실행: 저장 모델 평가

1. Python 3.10 이상과 Jupyter 또는 VS Code의 노트북 실행 환경을 준비합니다.
2. 터미널에서 `practice01/sungbin` 폴더로 이동해 의존성을 설치합니다.

   ```bash
   python -m pip install -r requirements.txt
   ```

3. `num2text.ipynb`를 열고 Python 커널을 선택합니다.
4. 첫 코드 셀의 `TRAIN = False`를 유지하고 모든 셀을 순서대로 실행합니다.

기본 실행은 새로 학습하지 않고 제공 모델 6개를 시험 데이터 전체로 평가합니다. 마지막 코드 셀에서는 모델을 파일에서 다시 불러와 6방향 번역 예제를 보여 줍니다. 노트북에 저장된 출력은 이 평가 모드로 실행한 결과입니다.

CPU에서도 실행할 수 있으며 CUDA를 사용할 수 있으면 자동으로 GPU를 사용합니다. GPU용 PyTorch는 환경에 맞는 빌드가 필요합니다. 작업 폴더는 `practice01/sungbin`, `practice01` 또는 저장소 루트여야 합니다.

### 번역만 사용하기

1~6절의 코드 셀을 순서대로 실행하고, 7절을 건너뛰어 8절의 마지막 코드 셀을 실행합니다. 이 경우 데이터 ZIP을 읽거나 전체 시험 평가를 하지 않습니다. 이후 새 셀에서 호출합니다.

```python
translate("12345", "num", "ko")
translate("twelve thousand three hundred forty five", "en", "num")
translate("만 이천삼백사십오", "ko", "en")
```

언어 코드는 `num`(숫자), `en`(영어), `ko`(한국어)입니다. **숫자도 반드시 문자열**로 전달합니다. `12345`가 아니라 `"12345"`입니다. 숫자 입력에는 0~9 문자만 허용합니다. 빈 입력이나 사전에 없는 토큰은 오류로 알립니다. 각 호출은 해당 방향의 모델 파일을 다시 읽습니다.

### 새로 학습하기

첫 코드 셀에서 `TRAIN = True`로 바꾸고 모든 셀을 실행합니다. 학습 데이터로 모델 6개를 차례로 학습하며, 검증 오차로 선택한 모델을 `new_models/`에 저장한 뒤 시험 평가합니다. 제공된 모델은 덮어쓰지 않습니다.

제공 모델을 다시 사용하려면 `TRAIN = False`로 바꾸고 설정 셀부터 다시 실행하세요. 실행 환경에 따라 새 학습 결과는 제공 모델과 달라질 수 있습니다.

## 3. 번역 원리 — 쉽게 설명하면

### ① 같은 숫자의 표현을 짝짓습니다

두 데이터 파일을 행 번호가 아니라 **숫자 문자열**로 연결합니다. 숫자→한국어 모델에는 숫자 문자열을 입력으로, 해당 한국어 표현을 정답으로 줍니다. 영어↔한국어는 두 파일에 모두 존재하는 숫자의 표현만 사용합니다.

### ② 입력을 작은 조각으로 나눕니다

숫자와 한국어는 문자 단위, 영어는 단어 단위로 나눕니다.

```text
"123"          → ["1", "2", "3"]
"백이십삼"     → ["백", "이", "십", "삼"]
"twenty three" → ["twenty", "three"]
```

이 조각을 토큰이라고 합니다. 토큰을 ID로 바꾸고 학습 가능한 벡터로 변환해 신경망에 전달합니다. 원래 숫자 문자열 자체를 정수로 바꾸어 계산하지는 않습니다.

### ③ GRU가 읽고 Attention을 참고해 출력합니다

```text
입력 문자열 → 토큰 → Encoder GRU → 입력 위치별 정보
                                      ↓ Attention으로 가중합
이전 출력 토큰 → Decoder GRU → 입력 정보와 결합 → 다음 토큰 점수
```

인코더는 입력을 순서대로 읽습니다. 디코더는 인코더의 마지막 상태를 받아 출력을 시작합니다. Attention은 매 출력 단계에 입력 위치별 중요도를 계산하고, 그 비중에 따라 입력 정보를 섞어 다음 토큰 예측에 사용합니다. 입력 한 위치만 고르는 방식은 아닙니다.

### ④ 정답과 비교하며 학습합니다

학습할 때는 이전 정답 토큰을 알려 주면서 다음 토큰을 맞히도록 합니다(teacher forcing). 정답의 예측 확률이 낮으면 오차가 커집니다. Adam으로 모델 가중치를 조정하여 이 오차를 줄입니다. 길이를 맞추는 PAD 토큰은 오차 계산에서 제외합니다.

### ⑤ 실제 번역에서는 스스로 생성합니다

시작 토큰 BOS에서 출발해, 매 단계 출력 가능한 토큰 중 점수가 가장 높은 하나를 선택합니다(Greedy). 선택한 토큰을 다음 단계의 입력으로 사용하며 종료 토큰 EOS가 나오면 멈춥니다. 시험 평가에서도 이전 정답을 알려 주지 않습니다.

## 4. 데이터 분할과 학습 설정

같은 숫자가 학습용과 시험용에 동시에 들어가지 않도록 숫자 키를 먼저 나누고, 모든 방향에 같은 분할을 적용합니다. 자릿수와 두 파일에 포함되는 여부별로 그룹을 나누어 약 80%/10%/10%를 배정합니다. `0`의 표현을 학습할 수 있도록 숫자 `0`은 학습용에 둡니다. 사전도 학습용 표현에서만 만듭니다.

| 방향 | 학습 | 검증 | 시험 |
|---|---:|---:|---:|
| 숫자↔영어, 숫자↔한국어: 각 방향 | 79,998 | 10,001 | 10,001 |
| 영어↔한국어: 각 방향 | 10,188 | 1,275 | 1,275 |

| 항목 | 설정 |
|---|---|
| 난수 시드 | 42 |
| 임베딩 크기 / GRU 은닉 크기 | 128 / 256 |
| GRU 층 수 / Dropout | 1 / 0.1 |
| 배치 크기 | 256 |
| 최적화 / 학습률 | Adam / 0.001 |
| 최대 학습 횟수 | 30 epoch |
| 조기 종료 | 검증 오차가 5회 연속 개선되지 않으면 종료 |
| 모델 저장 | 검증 오차가 이전 최저값보다 0.00001 넘게 감소하면 저장 |
| 기울기 최대 노름 | 1.0 |
| 생성 한도 | EOS를 포함해 최대 32단계 |

## 5. 저장 모델 평가 결과

공백을 정리한 **전체 출력 문자열이 정답과 일치하고 EOS로 종료해야** 정답입니다. 아래는 제공 모델을 제출 노트북으로 다시 평가한 결과입니다.

| 방향 | 정답 / 시험 수 | 정답률 |
|---|---:|---:|
| 숫자 → 영어 | 9,991 / 10,001 | 99.90% |
| 영어 → 숫자 | 9,996 / 10,001 | 99.95% |
| 숫자 → 한국어 | 9,997 / 10,001 | 99.96% |
| 한국어 → 숫자 | 9,998 / 10,001 | 99.97% |
| 영어 → 한국어 | 1,274 / 1,275 | 99.92% |
| 한국어 → 영어 | 1,272 / 1,275 | 99.76% |

영어↔한국어 공통 데이터에는 9~10자리 숫자가 없어 해당 범위를 학습·평가하지 못했습니다. 8자리 시험 데이터도 한 개뿐이며 두 방향 모두 오답입니다. 높은 전체 정답률이 모든 자릿수에서 같은 성능을 의미하지는 않습니다. 자릿수별 표본 수와 오답 예시는 노트북에서 확인할 수 있습니다.
